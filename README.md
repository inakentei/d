# Лабораторная работа №1

Репозиторий содержит исходный код интерактивного веб-приложения "Кликер" (Clicker Web App), упакованного в Docker-контейнер и развернутого в облачной инфраструктуре Render с автоматическим CI/CD пайплайном и персистентной базой данных.

* **Интерфейс мониторинга ресурсов и статуса:** [https://clicker-app-et6t.onrender.com/status/] /status
* **Метрики в формате Prometheus:** [https://clicker-app-et6t.onrender.com/metrics/] /metrics

## Технологический стек
* **Backend:** Python 3.11, FastAPI, Uvicorn
* **Database:** PostgreSQL (для сохранения состояния счетчика и почасового лога посещений)
* **CI/CD:** Docker, Render Blueprints
* **Monitoring:** Prometheus Client, Psutil (сбор метрик CPU, RAM, Disk, Uptime и Visits)

---

## Архитектура и выполненные требования

1. **Интерактивный интерфейс:** На главной странице реализована кнопка «ТЫК!», отправляющая асинхронные (`fetch`) POST-запросы к API. Счетчик мгновенно обновляется без перезагрузки страницы с помощью JavaScript.
2. **Персистентность (Сохранение данных):** Приложение подключено к СУБД PostgreSQL. Данные о количестве кликов и временных метках (лог посещений) надежно сохраняются в базу. При перезапуске, обновлении или "засыпании" контейнера данные не сбрасываются.
3. **Health Check:** Эндпоинт `/health` проверяет статус соединения с СУБД. Возвращает `200 OK` при стабильной связи и `503 Service Unavailable` при сбое. Данная проверка интегрирована напрямую в манифест контейнера через инструкцию `HEALTHCHECK`.
4. **Мониторинг ресурсов:** Реализована встроенная панель `/status` с визуальными таблицами, а также эндпоинт `/metrics` для интеграции с Prometheus. 

### Отслеживаемые метрики:
* `app_container_memory_usage_bytes` — потребляемая оперативная память процесса.
* `app_container_cpu_usage_seconds_total` — суммарное процессорное время, затраченное приложением.
* `app_container_memory_limit_bytes` — выделенный лимит RAM.
* `app_host_memory_available_bytes` — доступная память на хосте.
* `app_disk_free_bytes` — свободное дисковое пространство.
* `app_visits_last_hour` / `app_visits_last_24h` — количество посещений (кликов) за последний час и за сутки (метрика использования приложения).

## Описание процессов CI/CD, сборки артефактов и деплоя

В проекте реализован автоматизированный пайплайн непрерывной интеграции и доставки (CI/CD) на платформе Render с использованием технологии многоэтапной сборки (Docker Multi-stage builds).

### 1. Настройка сборки и сохранение артефакта (CI - Build Stage)
По триггеру `git push` в ветку `main` запускается изолированная среда сборщика (`builder`):
* Среда считывает файл `requirements.txt`, скачивает и компилирует все необходимые Python-зависимости.
* **Результат (Артефакт сборки):** Скомпилированные бинарные зависимости и библиотеки сохраняются в изолированной директории `/build/dependencies`. Это чистый артефакт сборки, отделенный от финального окружения.

### 2. Упаковка в контейнер и развертывание (CD - Deploy Stage)
* **Упаковка:** Процессы релиза создают чистый целевой образ (`runner`). Команда `COPY --from=builder` извлекает сохраненный на предыдущем шаге артефакт (библиотеки) и упаковывает его вместе с исходным кодом приложения (`app.py`) в финальный Docker-контейнер.
* **Развертывание:** Скомпилированный контейнер-артефакт регистрируется во внутреннем реестре (Registry) платформы и разворачивается на сервере развертывания Render.

### 3. Обеспечение персистентности («С сохранением данных»)
Согласно файлу конфигурации инфраструктуры `render.yaml`, контейнер автоматически подключается к выделенной облачной СУБД PostgreSQL. Изменяемые данные (общее количество кликов и логи посещений по часам) записываются во внешнюю базу данных. При деплое новых артефактов (обновлении кода) старый контейнер уничтожается, а новый успешно считывает и редактирует сохраненное в СУБД состояние счетчика.

## Инструкция по локальному запуску из исходного кода


### 1. Сборка Docker-образа (Артефакта)
```bash
docker build -t clicker-app-lab .
```

### 2. Запуск контейнера
Приложению для работы необходима СУБД PostgreSQL. Передайте строку подключения к вашей базе данных через переменную окружения `DATABASE_URL`:
```bash
docker run -d \
  -p 10000:10000 \
  -e DATABASE_URL="postgresql://username:password@host:port/database" \
  --name clicker_runtime \
  clicker-app-lab
```

### 3. Проверка локальных эндпоинтов
* Главная страница: `http://localhost:10000`
* Мониторинг в реальном времени: `http://localhost:10000/status`
* Метрики Prometheus: `http://localhost:10000/metrics`
* Хелсчек: `http://localhost:10000/health`
